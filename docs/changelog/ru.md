# Список изменений

Русская версия [CHANGELOG.md](../../CHANGELOG.md). Раздел версии показывается в «О программе» как заметки к обновлению.

## 0.2.0
Ресурсы и изменения, логи для LLM-ассистентов, локальные модели, Platform V DropApp и вход через OIDC.
- Platform V DropApp:
  - определяется по своим группам API, версия DropApp — в обзоре и для ассистента;
  - проекты — из проектов DropApp, VictoriaMetrics находится сама;
  - обзор кластера показывает компоненты, инструменты, узлы и сертификаты ingress DropApp; три новых правила проверки кластера;
  - глава руководства «Platform V DropApp».
- Вход через OIDC (Dex и другие провайдеры) в браузере: значения берутся из kubeconfig с `kubectl oidc-login` (у DropApp — того, что выдаёт Loginapp), токен обновляется сам; CA издателя задаётся отдельно.
- OpenShift 4.14 и более ранние: подключение больше не падает с 403, когда у сервера нет API SelfSubjectReview. Подключение с истёкшим токеном предлагает войти через браузер, дерево — войти снова.
- Ресурсы и изменения:
  - потребление CPU и памяти по метрикам кластера (Thanos, Prometheus, metrics.k8s.io) с графиками;
  - рекомендации requests и limits по фактическому потреблению;
  - изменения с проверкой на сервере (dry-run): requests и limits, масштаб, перезапуск, границы HPA;
  - ассистент может предложить изменение: вы видите его рядом с объектом и сами применяете или отклоняете.
- Логи для LLM-ассистентов: отдельный уровень доступа «Метаданные и логи», логи подов и поиск по логам workload'а с маскировкой значений, похожих на секреты.
- Локальные модели: подсказка формы аргументов, предел размера ответа (100, 48 или 24 КБ) и компактный набор инструментов для клиента; глава руководства «Локальная модель».
- Исправления по итогам смоук-тестов: очередь для долгих операций, журнал MCP с автообновлением, понятнее тексты.

## 0.1.0
Первая версия Glafira for Kubernetes — настольного приложения для чтения и диагностики кластеров Kubernetes, в первую очередь OpenShift.
- Подключения:
  - к API-серверам Kubernetes и OpenShift, в том числе по адресу с путём за прокси (Rancher);
  - вход через браузер (OAuth OpenShift), токеном, клиентским сертификатом или разрешённым exec-плагином;
  - импорт из kubeconfig, папки, экспорт и импорт;
  - секреты хранятся только в системном хранилище;
  - при подключении Glafira определяет платформу и проверяет, что вам доступно.
- Чтение кластера:
  - обзор кластера, ноды, проекты и workloads;
  - поды и их логи, события, сетевые объекты (Service, Route, Ingress, Gateway API);
  - конфигурация без значений Secret и ConfigMap, хранилище и квоты;
  - YAML и автообновление.
- Проверка кластера:
  - 34 правила: перезапуски по кругу, нескачиваемые образы, поды в Pending, недоступные workloads и застрявшие выкладки, requests, limits и пробы, Service без endpoints, проблемы Ingress, Route и Gateway API, квоты, PVC, HPA, операторы и ноды OpenShift;
  - строгость зависит от окружения подключения;
  - вкладка «Замечания» с фильтрами и скрытием, значки в дереве и таблицах, блоки на экранах объектов.
- MCP-шлюз для LLM-ассистентов (Claude Desktop, Claude Code и другие stdio-клиенты):
  - каждый клиент подтверждается в Glafira при подключении;
  - доступ LLM задаётся у подключения (выключен или метаданные всех либо перечисленных проектов) и не экспортируется;
  - значения, похожие на секреты, маскируются;
  - каждый вызов записывается в журнал MCP;
  - ассистент читает метаданные и запускает проверку; изменить кластеры он не может, его замечания хранятся в Glafira.
- Обновления из «О программе» → «Обновления», подписанные установщики для macOS (подпись и нотаризация Apple), Windows и Linux.
- Справка на английском и русском.
