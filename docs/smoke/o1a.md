# Смоук O1a (каркас и подключения)

Сборка: `pnpm tauri dev`. Кластеры: OpenShift Local (`crc start`, пользователи `kubeadmin` и `developer`) или
dev-кластер OpenShift; для kubeconfig — `oc login` в терминале заранее. Стенд kind (`dev/kind/README.md`) — для
пунктов про обычный Kubernetes. Для exec-плагина — кластер с входом через `kubectl oidc-login` (Keycloak, Dex)
или облачный (EKS — `aws`, GKE — `gke-gcloud-auth-plugin`, Yandex — `yc`), если он есть.

1. Первый запуск. В левой панели «Подключения» и подсказка «Добавьте первое подключение…»; в рабочей области
   «Выберите подключение слева или добавьте новое.». Внизу панели — «Настройки», «Поддержать проект», «Справка»,
   «О программе».
2. Вход через браузер. «+» → имя `crc`, адрес `https://api.crc.testing:6443`, «Способ входа» — «Браузер (OAuth
   OpenShift)», «Доверенный CA» — «Сертификаты (PEM)» с CA кластера (или «Не проверять (небезопасно)» для OpenShift
   Local). «Проверить подключение»: единственный шаг «Конфигурация» ❌ — «Войдите в кластер: кнопка «Войти через
   браузер»» (токена ещё нет, остальные шаги не выполняются). «Сохранить» → вкладка подключения с ошибкой и кнопкой
   «Войти через браузер». Нажать: открывается браузер со страницей входа OpenShift, после входа страница «Signed in —
   return to Glafira», вкладка показывает «Вход выполнен как developer», платформу «OpenShift 4.x» (у `developer` без
   прав на ClusterVersion — просто «OpenShift»), «Найдено в кластере» — «Route, Project, DeploymentConfig», версию и
   права.
3. Отмена входа. `oc logout` с токеном Glafira (или подождать истечения), «Подключиться заново» → «Войти через
   браузер» и, не входя, «Отменить»: ожидание «Ожидание входа в браузере…» прекращается, кнопка «Войти через браузер»
   возвращается, сообщения «Вход отменён» нет (остаётся только ошибка истёкшей сессии); вкладку браузера можно закрыть.
4. Страница токена. На вкладке подключения в блоке «Войдите снова» кнопка «Получить токен на странице кластера»
   открывает `https://oauth-openshift.apps…/oauth/token/request` (так входят на кластере без `openshift-cli-client`);
   скопировать токен, вставить в поле «Токен», «Сохранить токен» → вкладка показывает пользователя.
5. Токен. Новое подключение, «Способ входа» — «Токен», вставить `oc whoami -t`. «Проверить подключение»: все шаги с ✅,
   у «Проекты» — число проектов. Неверный токен → ❌ на шаге «Вход» с текстом «Кластер отклонил учётные данные», а шаг
   «TLS» при этом ✅: ответ сервера (401, 403…) — не ошибка TLS.
6. Импорт kubeconfig. Меню «⋯» → «Импорт из kubeconfig…»: путь `~/.kube/config`, текущий контекст отмечен, у
   контекстов с `auth-provider` или командой вне списка — причина и неактивный флажок. В «Папка для новых подключений»
   выбрать папку, «Импортировать 1 контекст» → «Импортировано 1 подключение»; у подключения в форме — проект контекста
   в «Избранные проекты», токен не показан (поле «оставьте пустым»). Повторный импорт того же контекста обновляет
   подключение («обновит существующее подключение»), не создаёт копию.
7. Клиентский сертификат (kind). Импорт контекста `admin` из `dev/kind/out/kubeconfig`: способ входа — «Клиентский
   сертификат», проверка — все шаги ✅, «Платформа» — «Kubernetes 1.x · API-сервер v1.x…»; на вкладке подключения
   «Найдено в кластере» — «—», пунктов «Операторы кластера» и «Версия кластера и обновления» нет. Вход через браузер
   на этом кластере → «На кластере нет OAuth-сервера OpenShift…».
8. Права. Контекст `dev-token` (kind): «Проекты» — ❌ «Нет прав: list namespaces на уровне кластера»; указать
   `team-a` в «Проекты (если список недоступен)» → ✅ «Кластер не отдаёт вам список проектов; проектов в профиле: 1».
   На вкладке подключения «Список проектов» и «Ноды» — «—».
9. TLS и прокси. Неверный CA → ❌ на шаге «TLS» «Сертификат сервера подписан недоверенным CA». Прокси «Адрес прокси»
   с несуществующим хостом → ❌ на шаге «DNS / TCP» «Не удаётся разрешить имя хоста сервера».
10. Политика. Из тестовой политики убрать ключ `language` (в примерах `docs/admin/` он `en`: интерфейс станет
    английским, и русские подписи не совпадут). Положить `docs/admin/policy.json` в
    `/etc/io.github.vvnovg.glafira.kubernetes/policy.json` (Linux) или профиль `docs/admin/policy.mobileconfig`
    (macOS), перезапустить: в форме варианты «Не проверять (небезопасно)» и «Exec-плагин» недоступны, сохранение и
    подключение с ними — ошибка «запрещены вашей организацией», в импорте kubeconfig контексты с exec-плагином
    неактивны; в «О программе» — «Политика организации»: «задана». Убрать политику.
11. Папки, экспорт и импорт. Новая папка, перетаскивание подключения, «Экспортировать всё…» → файл
    `glafira-kubernetes-connections-<дата>.glafira-kubernetes-connections.json` без токенов (`grep sha256~` пуст) и
    без секретных значений exec-плагина (п. 22); «Импортировать…» на другом профиле ОС → «После импорта введите токены
    или ключи для N подключений».
12. Prod. Окружение `prod` у нового подключения → флажок «Только чтение» отмечен, бейдж PROD красный, во вкладке —
    замок.
13. Удаление. «Удалить» в форме → «Удалить подключение «…»?» → «Да, удалить»: вкладки подключения закрыты, запись
    в keychain (`glafira-kubernetes`, `<id>/token`) удалена.
14. Справка и язык. F1 на форме подключения — глава «Подключения»; поиск «kubeconfig» в справке находит раздел
    «Импорт из kubeconfig». Меню «Справка» (macOS): «Руководство Glafira», «Поддержать проект», «О программе».
    «Настройки» → «Язык интерфейса» → English: интерфейс, руководство и меню на английском без перезапуска (меню Help:
    «Glafira Guide», «Support the project», «About Glafira»; F1 на форме подключения — глава «Connections»).
15. Данные. `~/Library/Application Support/io.github.vvnovg.glafira.kubernetes/connections.json` — `-rw-------`, без
    токенов и ключей клиентских сертификатов; секретные значения exec-плагина (п. 19) в нём есть — там они и хранятся.
16. Exec-плагин из kubeconfig. Импорт контекста с `kubectl oidc-login` (или `aws eks get-token`): в диалоге — строка
    запуска с полным путём (`/opt/homebrew/bin/kubectl …`), без флажка «Разрешить Glafira запускать эту команду»
    кнопка импорта неактивна. После импорта вкладка подключения: «Ожидание exec-плагина…», плагин открывает
    браузер, после входа — пользователь OIDC и платформа. «Отменить» во время ожидания → «Вход отменён».
17. Exec-плагин в форме. «Способ входа» — «Exec-плагин», команда `kubelogin` → «Найти» подставляет полный путь;
    переменная `OIDC_CLIENT_SECRET=…` в строке запуска скрыта (`••••`). «Проверить подключение» неактивна, пока не
    поставлена галочка «Разрешаю Glafira запускать эту команду»; после — шаг «Exec-плагин» ✅ со сроком учётных данных.
    Изменить аргумент и сохранить без подтверждения → вкладка подключения: «Подтвердите строку запуска exec-плагина…»
    и «Изменить подключение». Команда вне списка (`/bin/sh`) — ошибка «нет в списке разрешённых exec-плагинов».
18. Платформы. Кластер Kubernetes с Gateway API (kind с CRD Gateway API standard channel или облачный) — «Найдено
    в кластере: Gateway API»; EKS, GKE или k3s — дистрибутив в скобках («Kubernetes 1.31 (EKS)»). Адрес через прокси
    Rancher (`https://rancher…/k8s/clusters/c-…`), если есть: проверка проходит, платформа — «Kubernetes … (Rancher)»
    или по дистрибутиву нижележащего кластера.
19. Секреты в строке запуска. Контекст kubeconfig, где у `kubelogin get-token` есть `--client-secret s3cr3t` (или
    `--oidc-client-secret=s3cr3t` у `kubectl oidc-login`; у `aws eks get-token` — в `env`
    `AWS_SECRET_ACCESS_KEY=s3cr3t`): в диалоге импорта строка запуска показывает `--client-secret ••••`
    (`--oidc-client-secret=••••`, `AWS_SECRET_ACCESS_KEY=••••`), `s3cr3t` на экране нет. После импорта в форме
    подключения строка скрыта так же, а в `connections.json` лежит настоящее значение (не `••••`).
20. Подтверждение привязано к строке. Новое exec-подключение: поставить «Разрешаю Glafira запускать эту команду» —
    «Проверить подключение» активна. Изменить любой символ в «Команда», «Аргументы (по одному в строке)» или
    «Переменные окружения (ИМЯ=значение, по одной в строке)» — галочка снята, «Проверить подключение» снова неактивна;
    поставить галочку — активна. То же после смены «Способа входа» на «Токен» и обратно на «Exec-плагин»: галочка
    снята, нужна новая. У сохранённого подтверждённого подключения форма пишет «Строка запуска подтверждена» без
    флажка; смена на «Токен» и обратно без правок оставляет эту надпись, а правка аргумента возвращает флажок.
21. Kubeconfig изменился после предпросмотра. «Импорт из kubeconfig…», выбрать контекст с exec-плагином, поставить
    «Разрешить Glafira запускать эту команду»; не закрывая диалог, изменить аргумент плагина в файле kubeconfig
    и нажать «Импортировать 1 контекст»: подключение создано, но строка не подтверждена — на его вкладке «Подтвердите
    строку запуска exec-плагина…», в форме снова флажок «Разрешаю Glafira запускать эту команду». Тот же импорт без
    правки файла даёт подтверждённое подключение («Строка запуска подтверждена»).
22. Секреты exec-плагина и экспорт. Подтверждённое подключение с `--client-secret s3cr3t` (п. 19), «Экспортировать
    всё…»: в файле значение пустое (`--client-secret` и пустая строка следом; `--oidc-client-secret=`; пустой
    `AWS_SECRET_ACCESS_KEY`), `grep s3cr3t` пуст. «Импортировать…» этого файла в тот же профиль: подключение в группе
    «Без изменений» (если в файле поменять `apiUrl` и включить «Обновлять существующие подключения» — в группе
    «Обновятся»), значение в `connections.json` на месте, строка запуска остаётся подтверждённой. Импорт на другом
    профиле ОС: подключение без секретного значения и неподтверждённое («Подтвердите строку запуска exec-плагина…»).
23. Один запуск за раз. Подключение с `kubectl oidc-login`, плагин ждёт вход в браузере: пока идёт «Ожидание
    exec-плагина…», «Подключиться заново» неактивна, «Запустить exec-плагин снова» заменена ожиданием с единственной
    кнопкой «Отменить», в `ps` один процесс плагина; «Отменить» прекращает ожидание: «Вход отменён», процесс плагина
    завершён. Подключение с входом через браузер и истёкшей сессией: пока идёт «Ожидание входа в браузере…»,
    «Подключиться заново» неактивна, а «Сохранить токен» остаётся неактивной, даже если ввести текст в поле «Токен»;
    после «Отменить» кнопки снова доступны. У exec-подключения нет ни поля «Токен», ни кнопки «Войти через браузер».
